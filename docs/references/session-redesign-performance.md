## 不变量

- 每轮两个独立正常 worker；A 有 60 轮、每问 512 个 `x` 加固定前缀，答复为固定长度文本，B 执行固定 warmup。
- 先 warm 两次，再切会话 12 次；已有任务／分支面板切换 12 次；随后通过真实 composer 发起 40×20 ms 的流式答复。每轮实际 provider 请求均为 **87**，包括原生压缩和测量工具回合。
- 临时测量工具使用 `yolo` 免人工交互，仅作用于夹具；不改变生产默认审批，也不替代权限专项测试。
- 两个 worker 的 pid 必须与工具实际报告的 pid 一致。内存采样 50 ms；RSS 峰值使用 Linux `VmHWM`，heap 为 50 ms 的已观测峰值，不能声称捕获每个瞬时分配。
- 测量边界通过进程内公开 Inspector API 执行完整 GC，不开放调试端口。保留 GC 前值和 GC 后值；重复操作保留量比较前后 GC 后 heap，不能把 GC 后 RSS 冒充生产自然稳态。
- 不取消工作、不压短上下文、不省略 provider 请求；架构性增加的独立 worker 成本单列，优化只比较相同拓扑。

## 顺序约束

1. 真实创建并 warm 两个会话，完成固定历史，取得初始内存边界。
2. 浏览器确认正确 Agent、连接状态和第 60 条问题已展示，再记录历史就绪；切换需匹配实际 iframe owner，面板需可见。
3. 在相同浏览器／worker 实例内进行固定操作并保留请求与渲染观察。
4. 重复操作结束取内存边界；流式完成、worker idle 后等待 1.5 秒，取得稳态和最终边界。
5. 三轮全部完成才形成比较；后续优化沿用同一脚本与夹具指纹，字段或负载改变必须重建两侧基线。

## 错误模式

- 启动、HTTP、浏览器异常、采样失败、工具回执不匹配、负延迟或不完整三轮均失败，不记为有效结果。
- 探索期曾混用主页面与 iframe 的 `performance.now()`，负面板延迟整组排除；改为同一时钟且增加非负断言后重新采集。
- 扩展注册类型与 fixture assistant 的 provider 配置错误属于夹具错误；没有当作产品缺陷或优化收益。
- DOM 就绪延迟不是输入到实际绘制的硬件延迟；浏览器 readiness 轮询分辨率为 50 ms，流式首字小幅差异不可过度解读。

### 待定位的热点，而非已证实可删除的检查

- 已缓存会话来回选择仍有 15 次切会话请求及 15–17 次事件流打开，需检查是否重复重绑定或完整快照。相同目标、generation 失效、并发选择 A→B→A 与断连恢复必须区分，不能直接删请求。
- workspace／state 次数及 mutation 有计时噪声；以后收益必须超过这种波动，不能只取最好一轮。
- A 的 heap 峰值明显高于 GC 后保留值，需进一步区分序列化／投影临时分配与持久缓存；不能仅凭 RSS 高就删安全检查或宣称内存泄漏。
- 新独立分支增加的 worker 是新架构成本，不与这里的同拓扑优化混算。
