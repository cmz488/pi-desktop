# 原生自定义消息恢复续跑验收

日期：2026-10-16。对应此前目录整理中保留的原生压缩会话续跑失败。

## 复现与定位

原命令：

```bash
node --test --test-name-pattern='resume preserves native images' test/desktop-pi-sessions.test.mjs
```

修复前约 16 秒后超时：Agent 已空闲，最后一条仍是用户消息，HTTP 模型请求未发出。最小化对照显示，普通压缩、图片、工具结果可续跑；只增加自定义消息即失败，移除压缩或换成普通扩展类型仍失败。

导入路径对 `custom_message` 跳过了 Pi 的 `convertToLlm`，将原生 `role: custom` 放入只接受标准模型消息的 Durable `model` 字段。上下文估算将字符串内容当作助手内容块遍历，在访问块属性时抛出 `Cannot read properties of undefined (reading 'length')`。压缩会话的初始化估算提前返回，错误延迟到任务准备阶段，表现为界面空闲且没有回复；无压缩会话可能直接启动失败。这与网络、模型延迟及 Goal 卡片 renderer 无关。

## 修复

- 原生消息及上下文替换统一经 Pi `convertToLlm` 转换。自定义消息按 Pi 原生语义成为模型可见的用户消息；其类型、正文、展示标志与详情另存于 Durable 应用数据，继续投影卡片。
- 启动资源和恢复任务之前，检查旧记录当前生效的贡献，通过 Durable 上下文编辑修复不兼容角色。原始条目保持不可变；已修复的贡献不会重复迁移。
- 从旧条目分支时可能截掉父会话的修复条目，因此分支创建后同样检查其有效上下文。
- 表示层修复条目只更新 Desktop 同步水位，不导出为 Pi JSONL 用户上下文编辑；重建历史时使用保存的原生自定义消息。
