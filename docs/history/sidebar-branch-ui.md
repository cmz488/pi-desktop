# 分支导航与内联操作界面改进

## 范围与边界

本轮反馈针对左侧工作区／会话管理，而非右侧工具栏：创建分支后应在原工作区看到会话按钮，右键菜单应能创建继承目标当前位置的新会话。分支树操作移入轮次标签，悬浮或键盘聚焦显示；当前位置只创建分支，历史只退回。扩展工作台和全 Host 的任务与子代理界面一起简化。

继续复用 Pi Durable／Pi SDK；一个 Desktop Agent 一个 worker／SQLite／writer；历史 `parent` 与任务 `owner` 不混用。远程命令裁剪、只读管理门禁及不可变请求目标不放宽。不改真实会话、个人配置或现有安装；保留两份既有 release 包。

## 第一阶段：左侧分支会话导航

### 复现与根因

真实默认 Host／worker 加 Chromium 的回归先在「左侧会话右键菜单提供创建分支」失败；原生会话栏创建分支后，再在「原工作区分支按钮出现」失败。原生分叉本身成功，问题在外层导航只画 Desktop Agent，既无其历史会话的导航投影，也没有内层选择通知。

worker 的原子转录族清单追加原生记录的名称、来源摘要，Host 仅发布当前 generation 的导航字段。成功的 worker 命令同步该清单；观察类命令不更新时间戳。清单不是第二份会话上下文或权限真相，实际 fork 仍由原生 worker 执行。

左侧把历史分支列在原 Agent 之下，使用同一个外层身份和各自的数值会话 id。会话按钮、右键及 Shift+F10 固定原生目标；内外选择同步，刷新、停止及 Host 重启保留入口；客户端选择按 Agent／generation 存在 sessionStorage。停止的分支先显示启动入口，不能拿根会话的单份只读 JSONL 冒充该分支；启动后进入原数值会话。历史分支菜单不冒用外层进程的归档、人格或重命名操作。

### 原生命令转发

本地 `conversation.fork` 薄转发已有 tail fork。请求固定 Agent／generation／conversationId，转发时再次核对实际进程代际；只读、远程、未启动、非法／不存在目标均拒绝。忙碌时可快照，不中止源回合，不重放模型，也不添加 Desktop Agent。

新增 RPC 经过 SIGSTOP 红绿验证：旧路径挂到客户端 14 秒超时；修复后在 12 秒预算内返回 503，之后即便该 worker 仍暂停，也能继续 Host 元数据管理。超时只撤销 RPC 观察，提示刷新确认实际提交结果。

- 真实 HTTP：`desktop-sidebar-fork.test.mjs` 的 3 项通过；既有分支、归属和转录族专项的 11 项通过。两组分别执行，不作为最终统一 tree 的收口。
- `node test/desktop-branch-family-browser-check.mjs`：右键入口、原工作区按钮、零重放／零用量、源不变、内外切换、刷新、Shift+F10、多次退回后分支，以及停止／刷新后启动并进入同一分支通过。

## 第二阶段：轮次标签内联操作与设计方案

使用 frontend-design 与 ui-ux-pro-max；本地 UX 查询确认桌面 hover 应有反馈，但主要操作不能只依赖 hover，键盘聚焦与触屏须可用。密集清单样式只采用紧凑行距和可见焦点建议，不引入图表、KPI 卡片或新的框架。

- 浅色继续使用现有六色：画布 `#edf5f4`、面板 `#fbfdfd`、正文 `#263638`、次级文字 `#52666b`、强调 `#2f6970`、分隔 `#cfdddc`；深色对应 `#131d20`、`#233033`、`#e6f0ed`、`#afc0c0`、`#b4dcd5`、`#465b5d`。组件只引用语义 token。
- 正文沿用中文系统 UI 字体；13–14px 清单、11–12px 辅助信息，16px 局部标题。等宽字体仅用于原生标识或代码，不把整页结果做成终端。
- 对话以细轨道串联紧凑标签；SVG 保留真实展示路径，标签内的原生 HTML 按钮用于焦点与 disabled 语义。节点右侧预留操作位，避免悬浮时内容跳动。底部不再重复主操作。
- 任务以执行清单为主体，状态与按钮对齐；发起表单按需打开，结果详情与列表分区，窄屏纵向排列。
- 自检后放弃「卡片套卡片」方案：两张内置页入口缩成紧凑页签，去掉不适用于内置页的“会话记录／保留在原会话中”说明。保留其他扩展页原有类型与内容。

```text
对话分支  会话名                    最近 [10] 轮  刷新
│ 第 1 轮  提问摘要              [退回]       ← hover / focus
└ 第 2 轮  提问摘要  当前位置     [创建分支]   ← hover / focus

任务与子代理                              新建子代理  刷新
Agent / 会话   任务名             状态         等待  中止
任务列表                                  按需展开的结果详情
```

只改变展示和入口，不改变原生生命周期、确认、等待观察、代际与权限。

### 实现与验证

- 每个 SVG 轮次标签使用 foreignObject 中的原生按钮；当前位置仅 fork，历史仅 rewind。hover／focus 揭示操作，粗指针常显。底部只保留折叠摘要。
- 图形按容器宽度重排，默认 10 轮、最多 200 轮的显示窗口不变；细轨道、紧凑行与原位按钮替代大卡片。内置页入口压成页签，去掉错误的“会话记录”标签；其他扩展页语义不变。
- 真实细指针测试发现 headless 默认是 `hover:none`，已仅在隔离 Chromium 启动参数中显式指定细指针；保留产品触屏常显逻辑。Enter 事件补齐原生字符，不另写一套按钮键盘执行器。
- 双主题对比度测试捕获内置页签在主题切换时背景渐变、文字先变导致的 1.22:1 中间态；取消该背景过渡后，即时切换也满足 4.5:1。SVG 卡片按实际 fill 参与对比度测量。
- 轮次／工作台 Chromium 通过：真实 hover、Tab／Enter、刷新保留按钮焦点、每节点互斥动作、busy／只读、390px、触屏 44px、减少动态效果及浅／深色对比度。截图在 `/tmp/pi-sidebar-ui-check/screenshots/branches-{light,dark,narrow}.png`。
- `npm run check`、默认 Desktop 分支浏览器、Durable 浏览器、默认读面板浏览器及通用扩展工作台浏览器专项均通过。旧 Durable 用例改为按所选节点定位按钮，仍断言历史不能直接 fork；不能再把整个 DOM 中存在当前位置按钮误判为历史入口。

本节不替代最终全量验证与反向敏感度。

## 第三阶段：统一任务执行清单与阅读详情

工作台与 Host 复用同一个紧凑任务行：名称／原生状态、标识与所有权信息、操作分区对齐，使用已有 SVG 图标。中止仍需原身份下的两次独立点击；文案缩短为“确认中止”，等待取消、45 秒连接期限及续租逻辑不变。已有工具或子会话内容时不重复空任务指引。

全 Host 窗口默认收起发起表单，按需展开后聚焦任务输入，收起不丢草稿。桌面清单与详情并列，390px 下纵向排列；不再叠多层卡片或重复内核术语。原生回执按状态、子会话、用户／助手／工具和实时片段分区，以纯文本写 DOM，保留工具名和裁剪提示；不把空闲或 task 消失解释为 completed。详情更新保留滚动，同内容不替换正在阅读的节点。

真实 Host Chromium 的按需表单、草稿保留、同号任务 A/B 隔离、两步中止、独立等待、关闭／快速重开／Escape、图不变的真实两段流、结果、只读和焦点回归通过；工作台面板与真实长等待专项也通过。两处浅／深色文本对比度均达到 4.5:1，窄屏窗口边界通过。截图：`/tmp/pi-sidebar-ui-check/screenshots/{tasks,host-tasks}-{light,dark}.png`，另有 Host 运行态和窄屏图。

本阶段只修改 UI／文案／读视图；未改 task、submission、所有权、恢复、执行器、权限或远程协议。完整收口与隔离反向验证仍待完成。
