# Percho 界面迁移后的能力恢复

> 后续入口与组件已按 [Percho 原生能力整合](percho-native-ui-integration.md) 迁入左右侧栏及设置；本记录中的总工作台属于当时的过渡接线。

原界面替换后，一部分能力仍在 Host／Pi 中，但新界面没有入口，或沿用了形状不同的 Percho 协议。本次以原 pi-desktop 的行为为恢复基线，保留 Percho React 主界面，使用已有控制器、HTTP 接口和原生 Pi 生命周期。

## 使用入口

聊天页顶部的 **Pi 工作台** 提供以下功能。工作台会话选择只改变检查对象；模型执行与存储仍归对应 worker／Pi 会话所有。

| 入口          | 恢复的功能                                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话与进程    | 项目添加和配置、会话创建、Pi 历史接管、归档查看和恢复、进程启动／停止／重启、命名、置顶、人格选择、三档审批和显式项目信任                                                       |
| 扩展与任务    | 通用扩展卡片、声明式操作面板、分支树、任务和子代理详情、手动委托、等待与中止；关闭窗口释放观察，不中止实际任务，未提交表单及不确定提交的 requestId 保留在对应会话的客户端草稿中 |
| 文件与浏览器  | 项目目录树、文件预览、已有浏览器视图；Electron 继续使用原来的文件路径、选择器与浏览器桥                                                                                         |
| Git           | 已暂存／未暂存差异、批量暂存和取消暂存、提交、历史、分支、标签及原有受限管理操作；写入继续经过原生预览 token 和用户确认                                                         |
| Pi 设置与资源 | 人格和系统提示词、提供商和凭据、技能和模板、MCP、已安装包及包目录、Pi 配置、当前 Agent 的模型／工具／扩展／工作目录／Shell 环境配置                                             |
| 侧聊          | 已加载 pi-btw 时查看、提问和取消独立讨论，将回答带回该会话的输入框；未加载时显示明确空态                                                                                        |

输入框支持本机路径引用、拖放、剪贴板文件和浏览器文本附件。文件补全按目录逐层展开；实际模型输入使用绑定路径，界面保留用户可读标签。发送会等待附件准备，并保留失败草稿。扩展的状态栏、标题、编辑器镜像、工具展开和工作指示也接回真实消费者。

`/git`、`/settings`、`/models`、`/login`、`/logout`、`/skills`、`/mcp`、`/sessions`、`/resume`、`/new`、`/session`、`/copy` 和 `/help` 恢复对应界面操作。提示模板的 `prompt` 来源转换为 Percho 的 `template`，扩展和技能命令可在补全中选中并交给 SDK 原生执行。`/btw` 打开独立侧聊。

消息菜单中的精确分叉、用户输入退回和导出绑定原生条目 ID。退回发生在对应用户消息之前，并在提交事务中拒绝运行中的任务；保留原树，不重写 JSONL，也不伪造模型输入。JSONL 导出包括原生 header 和完整条目。

## 修正的接口边界

- 提供商保存使用原生 provider／apiKey／model 配置及 revision；API Key 和 OAuth 经原生交互 job。取消登录只取消对应 job，删除凭据才调用 logout。同一个登录交互只由一个界面消费者负责。
- MCP 的配置清单转换为 `global/project`，写入使用原生 CRUD action、scope 和 revision；配置已保存与资源已重载分别报告。
- Git 操作绑定 cwd 和原生会话；分支切换使用 `/api/git` 的预览／确认协议。
- 文件清单转换为补全所需路径数组。文档的模型文本、显示原文和引用绑定由共同校验函数检查。
- 自定义卡片、自动输入来源、输入原文、精确 entryId 和实时工具输出得到保留；已提交调用的实时输出原位更新，避免同时在流式区再出现一份。
- 复用设置控制器时，先建立上下文再注入 inventory，避免首次加载清掉提供商／包和 revision。共享对话框转发控制器动作，修复“自定义兼容服务”等按钮无响应的问题。
- 扩展的 `setWidget(string[])` 按字符串行渲染；普通组件使用既有卡片／状态投影并保留有界正文，SDK 快照中独立的 widgets 只在界面视图合并，不写入模型历史。
- Pi 的三档审批保留在工作台；Percho 的两档控件不会将现有“全部确认”降为“风险操作确认”。

## SDK Web／TUI 兼容入口

兼容路径使用真实 UUID、原生会话文件和 `/api/sessions` 返回值，支持新建、命名、重开及关闭。后台 slot 的请求通过 AsyncLocalStorage 绑定目标，跨 await 不借用当前聚焦 slot，移除／替换中的旧目标被拒绝。读取或提交 A 不切换 TUI 的聚焦 B。

兼容宿主的展示偏好由通用 bridge 服务，保存到 `agentDir/desktop-ui/`，与 Pi 会话、模型和 settings 文件分开。日常入口复用 Pi 的当前工作目录；不同工作目录仍由原 Pi 宿主管理。没有对应能力的分支、归档和审批控件不伪装可用。

Percho 的 SSH、更新器、UI 插件运行时等独有子系统仍显式 unsupported；Tailscale 和旧公网方案不恢复。当前支持表为 **64 个 invoke、6 个订阅**，这只是协议登记数量，不能代替实际功能验收。

## 后续审查：缺失接口与客户端异常

继续审查复现了背景图选择、UI 插件开关和更新检查的未捕获异常。启动链虽然已跳过相关服务，设置页仍能调用这些不存在的接口。现在根据实际支持表挂载控件，移除不可用的 SSH 入口和子代理定义配置；原有任务委托仍在 Pi 工作台。关于页的操作失败显示局部错误并可重试，包括方法缺失时的同步异常，不再成为未处理的全局异常。

`forEnvironment` 现在拒绝不支持的 SSH 环境，而不是返回本地 API。回归经过真实 Percho 环境绑定函数，验证同号远程会话既不能写入本地，也不能订阅本地事件。空 Host 的清单读取返回空数组，不偷偷启动 worker；已请求启动的 worker 继续沿用既有等待流程，真实 503 仍会传递。

权威快照增加模型、思考级别和可用审批模式的配置投影，客户端只更新对应已加载会话的展示状态，不重新发起模型变更。原生设置修改和会话切换也会刷新当前目录的模型清单，修复后端已换模型而界面停留在旧值的问题。

`test/ui-capabilities.test.mjs` 覆盖环境隔离、空 Host 和真实错误传播；`test/ui-capabilities-browser-check.mjs` 复现并拦住未处理异常，验证正常主题仍可用、操作错误可见且可重试。现有页面验收追加原生接口改变模型后的实际显示断言。

## 验证

```sh
npm run check
npm test
npm run test:ui-next:browser
npm run package:check
```

`test/ui-parity.test.mjs` 使用临时真实 Host／SDK 和 Percho 纯消费者，覆盖已复现的配置、文件、UUID 生命周期、精确分叉／退回、原生导出、Git、登录交互和投影。

`test/ui-parity-browser-check.mjs` 使用临时项目和本地模型，通过真实 Percho 页面操作聊天、扩展命令／卡片／状态、任务草稿／子代理、文件、Git 暂存及确认提交、提供商保存、独立侧聊及带回；检查窄屏和深色主题，并拒绝未预期的 HTTP 失败和运行时异常。

`test/ui-compat-browser-check.mjs` 使用真实 SDK Web 入口，验证 UUID 会话的实际发送、原生工具和回复，以及兼容模式的 API 消费。测试不使用个人配置、真实模型账号或真实项目。`npm run test:tui` 另用真实 PTY 验证 `/desk`、原生／SDK 并行会话及退出清理。打包检查先运行项目的 prepack，确保验收的是当前源码构建出的资产。系统文件选择器、真实 OAuth 账号授权及真机证书首次信任仍需相应平台的人工验收。
