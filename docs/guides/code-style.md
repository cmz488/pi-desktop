# 代码与文档规范

本规范约束 `src/`、`test/`、`scripts/`、`docs/` 的新增与修改内容。目标是「执行代码即文档」：**代码本身是唯一权威**，注释解释意图与约束，文档解释契约；两者都不复述对方。

## 总则

1. **代码是权威**：任何描述都必须能在源码里被验证；文档过期时以代码为准，并同步修正文档。
2. **中文优先**：新增或修改的注释、文档、面向用户的错误消息用中文；代码标识符、协议字段名与上游术语（Harness、entry、commit、document、task、submission、seam、adapter、capability、runtime）保留英文，首次出现时给出中文解释。
3. **不做无意义重写**：不为了统一语言批量改写未触及模块的既有英文注释；只在改动到的位置遵守本规范（避免产生巨大而无关的 diff）。

## 规则 1：注释只写「为什么」与不变量

**判据**：读一遍注释，如果它描述的内容能从紧邻的代码直接读出来，就是违规。

- ✅ 正例：`// Electron 使用自带的 Node 运行时，与 DSH 的 RunAsNode Host 边界保持一致。`（解释为什么用 `ELECTRON_RUN_AS_NODE`）
- ✅ 正例：`// 分叉可能停在父会话的修复条目之前，从而再次继承旧的 custom 贡献。`（解释为什么必须再修一次上下文）
- ✅ 正例：`// 资源 Session 永远不跑第二个模型循环。`（不变量）
- ❌ 反例：`// 遍历会话并取摘要`（复述代码）
- ❌ 反例：`// 这里可能出错，先 try 一下`（没有约束信息，等于没写）
- ❌ 反例：`// TODO 之后补上`（没有对象、条件与触发时机）

## 规则 2：模块顶部契约块

**何时必须有**：模块被 `docs/architecture/interfaces/` 覆盖，或导出的函数会被其他文件调用。每个这样的模块在 imports 之后、第一段实现之前放一个契约块。

```js
/**
 * <模块名>：<一句话职责>
 *
 * 接口：<调用者必须知道的入口与其语义；细节见 docs/architecture/interfaces/<契约>.md>
 * 不变量：<任何时刻都成立的事实，可用分号分隔多条>
 * 错误：<抛出的类型与判定条件>
 */
```

- ✅ 正例：契约块能回答"能不能这样调用、并发时会不会打架、失败时是抛错还是返回空"。
- ❌ 反例：契约块写成实现步骤（"先建 Map，再逐条读取"）——违反规则 1。
- ❌ 反例：只有一句话"工具模块"，没有接口或不变量——等于没有契约块。

## 规则 3：接口与实现分离

| 内容                                                   | 归属                                     |
| ------------------------------------------------------ | ---------------------------------------- |
| 调用者视角：签名、不变量、顺序约束、错误模式、性能特征 | `docs/architecture/interfaces/<契约>.md` |
| 实现原因、取舍、上游限制、历史演进                     | 源码注释与 `docs/history/`               |
| 运行归属（谁拥有什么）                                 | `docs/architecture/pi-boundary.md`       |
| 领域术语                                               | `CONTEXT.md`                             |

- ✅ 正例：源码契约块写"接口见 docs/architecture/interfaces/pi-sdk-adapter.md"，接口文档写"未加载时调用会抛错"，源码写"为什么需要懒加载"。
- ❌ 反例：把实现细节（内部缓存名、私有结构）写进接口文档。
- ❌ 反例：把接口文档整段复制到源码契约块，形成两处需要同步的副本。

## 规则 4：中文术语与命名约定

术语以 [CONTEXT.md](../../CONTEXT.md) 为准，常用对照：

| 术语                         | 含义                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| Harness                      | Durable 的持久化 agent 执行引擎                            |
| entry / commit / document    | 不可变的转录记录 / 原子写入 / 附在会话上的类型化 JSON 状态 |
| task / submission            | 存检查点的持久状态机 / 交给会话并可等待的工作              |
| seam                         | 可以在不改动该处的情况下改变行为的位置（接口所在处）       |
| adapter                      | 坐在 seam 上满足接口的具体实现                             |
| capability                   | Host 显式声明、bridge 只按声明调用的能力位                 |
| 资源会话（resource Session） | Pi 提供工具、扩展、技能、MCP 与交互的会话                  |

命名与排版：

- 文件名与文档名用 `kebab-case`（`durable-resources.mjs`、`code-style.md`）；函数与变量 `camelCase`；常量 `UPPER_SNAKE_CASE`；类与类型 `PascalCase`。
- 中文与英文／数字之间加空格；中文用全角标点，代码、路径、字段名保持半角。
- 错误消息面向使用者，句式固定为「<对象>无效」「请先 …」「…正在被另一个宿主占用」；不泄露绝对路径、凭据或内部标识。
- 注释不写"简单／复杂／优化"这类主观描述；要给出可验证的理由。

## 判定示例

| 片段                                                          | 判定           | 说明                                                 |
| ------------------------------------------------------------- | -------------- | ---------------------------------------------------- |
| `// 把消息发给模型并等待结果`                                 | 违规（规则 1） | 复述代码，删除即可，信息量为零                       |
| 一个 400 行的 `xxx-manager.mjs` 没有契约块                    | 违规（规则 2） | 它被接口文档覆盖，调用者需要知道不变量与错误模式     |
| 在 `interfaces/host-interface.md` 写"内部用 WeakMap 缓存操作" | 违规（规则 3） | 实现细节应留在源码；接口文档只写调用者必须知道的事实 |
| `// TODO 修复`                                                | 违规（规则 4） | 缺少对象、条件与语言约定                             |
| `throw new DeskError(409, "Agent 存储正在被另一个宿主占用")`  | 合规           | 中文、面向用户、不泄露路径                           |

## 落地方式

本轮**不引入自动检查器**（用户选择"只写规范文件"）。评审按下述清单核对，互相印证：

1. 新增注释是否只解释为什么／不变量（规则 1）。
2. 被 `docs/architecture/interfaces/` 覆盖的模块是否有契约块（规则 2）。
3. 契约是否写在接口文档而不是散落在调用点（规则 3）。
4. 术语是否与 `CONTEXT.md` 一致，错误消息是否中文且面向用户（规则 4）。
5. 改动是否附带可执行证据（测试文件名或命令）——见 [接口契约](../architecture/interfaces/README.md) 的"可执行证据"小节。

规范与运行归属、验证方式的关系见 [贡献说明](../../CONTRIBUTING.md)、[源码地图](../architecture/source-map.md) 与 [验证说明](../architecture/verification.md)。
