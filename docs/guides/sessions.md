# 项目与会话

左侧添加项目时使用系统文件夹选择器；会话按 Pi 的 cwd 归入项目，也支持无项目对话。选择另一个 Agent 会保留后台进程和各自草稿；聊天“停止”取消当前任务，右键“停止进程”关闭 Agent。

Pi TUI 与 Desktop 的活跃记录均使用 `~/.pi/agent/sessions/<encoded-cwd>/*.jsonl`；兼容发现已有 `session/` 目录。Desktop 能查看 TUI 历史，在退出该文件的原 TUI writer 后选择“在 Desktop 中继续”。继续对话保持原 session ID，仍使用 Pi 的模型与工具运行链。

## 崩溃与定点重启

Agent worker 被杀死或异常退出后，它未完成的回合留在 Durable 存储里。重新启动该 Agent 时，新宿主接管这些任务：已提交且不依赖中断工作的条目不会被重发，未完成的生成会被重新发起，可安全重放的工具会重跑，中断时无法确认结果的一次性副作用不会重跑，而是作为错误结果写入转录。

接管后 `/api/state` 的 `recovery` 字段（以及聊天页状态旁的“已从检查点恢复 N 项”提示）会显示本次接管的待恢复任务与仍在进行的数量；恢复完毕后该数量归零，提示自动消失。已中断的尝试本身会保留一条标记记录，它与恢复后的新尝试都会计入用量，因此恢复后的会话用量高于未中断的同一会话；被杀死进程的租约需要约 10 秒到期，期间不能启动第二个 writer。

## 退回与分叉

右键任意消息可以打开两个动作：

- **退回到此消息**：模型上下文重建到该消息（之前的内容保留，其后的回合从上下文移除，但仍留在 Pi JSONL 会话树与原生日志里，仅供查看）。随后继续对话就从该点接着走。
- **从此消息分叉**：从该消息创建一个独立会话（名称带“· 分支”），拥有分叉点之前的上下文与自己的用量，源会话不受影响。

右侧会话栏右键任意会话有三个动作：**创建分支**（按该会话当前上下文分叉出一个新会话，立即出现在会话栏并带自己的用量）、**退回分支**（退回该会话的最后一条用户消息，上下文从那里重建；该会话没有原生 Pi 记录时该项禁用并说明原因）、**打开分支树**（切到扩展工作台的分支树面板）。行获得焦点后按菜单键或 Shift+F10 也能打开同一菜单。

退回在同一个 Pi 会话文件里完成：原生日志的活跃条目（leaf）移回到该消息，新回合成为它的子条目，被放弃的分支留在文件里，因此 Pi TUI 看到与 Desktop 相同的会话树。退回需要该 Agent 的原生转录：默认多进程 Desktop 每个 Agent 都有；单进程或注入 workspace 的宿主只为主启动 Agent 绑定转录，其他会话退回会提示无法退回（分叉仍可用）。

## 归档与恢复

归档先在 Desktop 数据目录的 `session-archives.sqlite` 保存完整 JSONL 树，成功后移除原 JSONL，使 Desktop 与 Pi TUI 都默认隐藏。归档查看只读 SQLite；恢复将原记录原子写回原目录和文件名，保持 session ID，遇到内容不同的已存在文件时拒绝覆盖。

运行中、启动中、停止中的 Desktop Agent 或被 Pi TUI 占用的会话不能归档，须先停止对应进程。Pi TUI 不遵守 Desktop 写锁；同一个 JSONL 不应同时由两个 writer 修改。外部更新后的接管沿用现有冲突检查。

历史发现只读索引，进入后加载有界消息页；工具与思考正文展开时再取，切换客户端不会停止其他 Agent。
